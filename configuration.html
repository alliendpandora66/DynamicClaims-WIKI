Configuración Técnica (YAML) y Referencia Completa

Todos los archivos de configuración se alojan en plugins/DynamicClaims/. Las claves del sistema utilizan minúsculas separadas por guiones (kebab-case, por ejemplo morale.morale-recovery-per-chunk), mientras que los IDs personalizados que defina tu servidor (como industria_mineria_profunda, tanque o vip_plus) conservan su identificador exacto.

1. Validación Estricta y Respaldos Automáticos

Al iniciar el servidor o ejecutar /dc admin recargar, el catálogo de configuración verifica los 24 archivos YAML editables:

  • Protección ante Errores de Sintaxis: Si un archivo YAML contiene tabuladores inválidos o un tipo incompatible, la recarga aborta el lote afectado y mantiene la configuración anterior en memoria sin sobrescribir ni perder tus cambios.
  • Respaldo Automático antes de Migrar: Si el plugin detecta claves históricas con guion bajo (_), crea primero una copia íntegra en plugins/DynamicClaims/backups/configurations/FECHA-ID/ y luego escribe el archivo actualizado mediante CoalescedAsyncFileWriter.

3. Desglose Completo de `config.yml`

A. Nametags Relacionales, Combate y Relaciones

nametag:
  enabled: true
  mode: SUFFIX # SUFFIX, PREFIX o BOTH
  suffix-format: " &7[{nation_color}{nation}&7]"
  relation-colors:
    same: "&a"
    ally: "&9"
    neutral: "&e"
    enemy: "&c"
  preserve-existing-format: true # Conserva rangos de LuckPerms / TAB
  tab-integration: true          # Coordina equipos con el plugin TAB
  sync-tablist: true
  tablist-format: "{external}{suffix}"

combat:
  combat-tag:
    enabled: true
    duration: 15                 # Segundos de Combat Tag activo
    prevent-teleport: true       # Bloquea comandos de teletransporte en combate
    only-in-war: false           # true = solo etiquetar dentro de zonas de guerra activa
    punish-on-logout: true       # Mata al jugador si se desconecta en combate
    action-bar: '&c&l⚔ EN COMBATE ⚔ &7| &fQuedan &e{time}s &7| &c¡No te desconectes!'
  relation-colors:
    enemy: '&c'
    ally: '&a'
    same-nation: '&b'
    neutral: '&7'

B. Tiempo del Servidor (Zona Horaria Real) y Calendario Roleplay

server-time:
  timezone: "America/Mexico_City" # Zona horaria para programar guerras y eventos
  network-time-sync: true         # Sincroniza reloj con API pública (timeapi.io / Cloudflare)

time:
  day-duration-seconds: 1200      # 1200s (20 min reales) = 1 día del calendario RP
  start-date: "01.01.2000"        # Fecha inicial en formato DD.MM.YYYY
  sync-minecraft-time: true       # Sincroniza el sol/luna de Minecraft con la hora RP
  disable-daylight-cycle-on-sync: true
  sync-worlds: []                 # Vacío = todos los mundos NORMAL; o ["world", "earth"]

5. Configuración de Árbol Tecnológico (`tecnologias.yml`) y Rangos (`rangos.yml`)

En tecnologias.yml puedes definir nodos científicos con prerrequisitos, fechas mínimas de desbloqueo (según el calendario RP) y efectos automáticos de permisos o bonificaciones:

tecnologias:
  industria_manufactura:
    category: industria
    name: "&e Manufactura"
    description: "&7 Desbloquea la produccion en masa de bienes industriales"
    points: 250
    date: "15.06.2001"            # Fecha mínima requerida en el calendario del servidor
    requirements:
      - industria_fundicion
    effect:
      - "permiso: wwc.dc.industria_manufactura"
      - "boost: investigacion.10" # +10% velocidad de investigación por ciclo

En rangos.yml defines los rangos reclamables en /dc rango con recompensas únicas y periódicas:

rangos:
  vip_imperial:
    display-name: "&6&lImperial"
    prefix: "&8[&6Imperial&8] &r"
    permission: "dynamicclaims.rank.imperial"
    one-time-reward:
      auto-deliver: true
      commands:
        - "eco give %player% 5000"
    rewards:
      cooldown-hours: 24
      commands:
        - "give %player% gold_ingot 16"
